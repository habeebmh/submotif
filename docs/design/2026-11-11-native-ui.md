# Native software: Undertow editor simplification

The UNDERTOW by Habeeb identity uses lime on neutral charcoal. Avenir Next gives the macOS development build one readable type family; regular and medium-weight text, 13–15px controls, 26px wordmark. Equal 28px edges and consistent spacing replace stacked outlined cards. Version 1.2.0 simplifies both the native VST3 editor and the Max for Live device. The weighted composition algorithm is retained; new instances start in C minor at C1 with a one-bar loop.

The user asks for a simpler, usable and beautiful VST interface, and explicitly invokes design-taste-frontend. Its hierarchy, copy, aligned edges, single design system, visible focus and press/hover feedback apply to this native JUCE application. Website-specific HTML, hero, photographs, page sections, mobile widths, shaders and Chrome gate do not apply. No website gate pass is claimed. Native editor screenshots, interaction tests and pluginval are the acceptance evidence.

Voice: short, practical production-tool labels. Primary action Generate; secondary Change a few notes and Drag MIDI. Actual data only. No marketing claims or decorative telemetry.

## Chosen design

- Compact 920×560 default VST3 editor, with an 820px minimum width and 1380px maximum width. One uninterrupted workspace; subtle piano-roll grid and readable pitch rows without a separate velocity lane. Velocity remains in note tooltips and exported MIDI.
- A compact Style dropdown selects Deep House, Rolling, Offbeat, Acid, Disco or Funk. Key, Scale and Length sit beside it. This replaces the earlier proposal's large style-button row.
- Density and Melody (underlying Movement) are horizontal controls with readable values. More controls expands the window to 920×700 at base scale, adding Swing, Note length, Register, Root notes only, Start on root and Octave jumps. The resize checks the display's usable bounds and reduces width when necessary within the supported size limits. Disclosure preserves values and removes hidden controls from keyboard traversal.
- Generate is the only solid lime action, at 140×38px. Change a few notes is a quiet 160×38px secondary action, separated by 6px. Drag MIDI is a compact outlined target; clicking it still saves a file, and Help retains an explicit Save MIDI menu item.
- Undo/Redo sit with the piano roll. Unlock all appears only when notes are locked. Live MIDI stays visible, with a brief host/output state. Help contains routing instructions, Save MIDI and Stop notes.
- Changing controls preserves the displayed notes until Generate. Change a few notes becomes unavailable while settings are pending, and its handler also guards against applying them. A pending-change cue directs the user to Generate. Export remains the exact displayed phrase. Errors and removed-lock notices remain visible. No remembered project state is rewritten by disclosure or styling.

## Max for Live

The Max device uses the same charcoal/lime system and plain labels within Live's fixed-height device view. Its compact presentation is 1000×169px. More controls expands it sideways to 1260×169px, revealing Swing, Note length, Register, the pitch switches and Stop notes. Fewer controls hides those items without changing settings, notes, locks or history. Generate and Change a few notes have the same pending-setting behavior as the VST3 editor.

Create clip and Save MIDI remain explicit Max actions; direct operating-system MIDI drag-out belongs to the VST3 edition. Existing Max parameter names are retained for saved sets and automation: Melody is still `Movement`, Note length is `Gate`, and Register is `Octave`. Both editions recall existing saved notes, settings and locks exactly. C1 and one bar are defaults for new instances only.

## Alternatives considered

Keeping all controls with lighter styling would leave the same choice burden. A wizard would hide the phrase or interrupt repeated generation. Progressive disclosure keeps the core loop on one screen and preserves access to the full existing feature set. This is an implementation choice within the user's redesign request.

## Verification

Build the actual VST3/standalone and Max device. Inspect deterministic native captures in compact, expanded, minimum and enlarged states. Test control visibility, disclosure resize/focus, setting retention, generation, undo/redo, MIDI output, locks and visible control bounds. Check Max width/visibility messages, matching defaults, preserved parameter names and saved-state compatibility. Run existing processor/core/Max/parity checks and pluginval. Host observations and remaining checks are recorded separately in [Validation](../VALIDATION.md); this design document does not claim host success. Keep release packaging on hold.
